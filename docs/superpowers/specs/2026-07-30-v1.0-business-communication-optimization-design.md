# V1.0 商务沟通优化升级设计

## 目标与边界

将 Leon AI 从英文邮件生成与优化工具升级为“AI 商务沟通优化助手”，同时保留现有生成、优化、复制、动态签名、访问码和 DeepSeek 连接方式。

本次增加本地敏感信息预检、地区与称谓建议、商务沟通质量分析、案例演示、使用说明及 V1.0 品牌信息。不增加数据库、用户注册、支付、额度、历史记录或其他范围外功能。

系统不持久化用户输入、分析或生成结果。Streamlit `session_state` 仅用于当前交互会话，不写入文件、数据库或日志。

## 模块边界

### `config.py`

保存统一版本和产品名称常量，继续负责 DeepSeek 配置，不改变当前默认模型、基础地址或 Secrets 读取规则。

### `content_risk_service.py`

负责本地、确定性的提交前检查：

- 风险等级：`low`、`medium`、`high`
- 风险项目：类别、掩码描述、建议
- 正则检测凭证和长数字
- 关键词检测机密、财务、法律及承诺风险
- 不返回或记录完整敏感原文

高风险包括疑似 API Key、Access Token、密码、验证码、身份证件、护照、银行卡或其他凭证。商业机密、报价、成本、合同责任、赔偿、确定交期或保证完成通常为中风险；只有凭证或高度明确的敏感标识才升级为高风险，避免普通商务内容被过度阻断。

### `localization_service.py`

负责国家/地区选项、称谓建议和跨文化提示。输入为收件人、地区、可选自定义地区、语气及原始内容；输出为推荐称谓、称谓风险、礼貌建议和简短本地化提醒。

规则只提供建议，不覆盖用户输入，不根据姓名推断性别、婚姻、宗教、族裔或其他敏感属性。不确定时要求用户核对邮件签名、名片或正式资料。

### `communication_analysis_service.py`

定义分析结果结构及降级逻辑，保证字段缺失时仍能渲染。维度包括：

- 沟通目的
- 行动要求
- 截止时间
- 商务语气
- 承诺风险
- 歧义风险
- 本地化提示
- 改进建议

只使用“良好”“建议检查”“需要修改”等文字，不使用虚假百分比或安全保证。

### `examples.py`

保存四个结构化案例：

1. 供应商交期催办
2. 印度尼西亚客户会议邀请
3. 马来西亚管理层正式汇报
4. 英文邮件优化

案例按钮只填充相关页面状态，不调用 DeepSeek。

### `prompts.py` 与 `ai_service.py`

沿用现有单次 DeepSeek 请求和一次修复性重试。正常生成与优化返回：

```json
{
  "subject": "",
  "body": "",
  "communication_analysis": {
    "purpose": "",
    "action_required": "",
    "deadline": "",
    "tone": "",
    "commitment_risk": "",
    "ambiguity_risk": "",
    "localization_note": "",
    "improvement_suggestions": []
  }
}
```

AI 不生成签名，Python 继续在本地添加签名。提示词要求保留事实、不虚构、不输出用户中文原文，并明确风险分析仅是辅助提示。

### `app.py`

只负责页面渲染、输入收集、临时 session 状态、服务调用和结果展示。风险、本地化、案例和分析规则不堆积在页面文件中。

## 处理流程

1. 用户选择生成或优化模式。
2. 填写现有字段及收件人国家/地区。
3. 本地执行敏感内容检查。
4. 显示低、中或高风险状态以及人工建议。
5. 高风险时显示“我已检查并确认内容可以提交给 AI 处理”复选框；未勾选时不调用 API。
6. 本地生成称谓与本地化建议。
7. 用户主动点击后发起原有 DeepSeek 请求。
8. 解析邮件和沟通分析。
9. Python 添加动态签名。
10. 显示分析、邮件、复制与编辑区。

页面打开、风险检查、案例填充、地区切换和访问码验证均不调用 DeepSeek。

## 风险显示与隐私

- 低风险：显示“未发现明显敏感信息，但仍请确认内容符合公司保密规定。”
- 中风险：显示注意状态，可继续处理。
- 高风险：显示高风险状态，必须人工确认后才允许提交。
- 状态同时使用文字、图标和标题，不只依赖颜色。
- 身份证件、账号、Token 等只显示类别和掩码说明。
- 不在日志中打印输入、命中原文、访问码、API Key 或完整异常。
- 固定声明：“本功能仅提供辅助检查，不能替代公司的保密制度及人工审核。”

## 本地化规则

国家和地区选项与附件保持一致。选择“其他”时显示可选自定义输入。

- 未指定：给出通用、非推断式称谓建议。
- 印度尼西亚：如用户已提供 Pak/Bu，提示核对使用习惯；否则优先 `Dear + Name`。Pak 通常用于男性、Bu 通常用于女性，但不得由系统自行添加或推断。
- 马来西亚：识别并建议保留 Dato'、Datuk、Tan Sri、Dr. 等已提供头衔；无法确认时使用全名并提示核对正式资料。
- 新加坡：正式初次联系优先全名或已确认头衔；熟悉关系可结合对方习惯使用名字。
- 越南：不推断姓名组成，参考对方自我介绍或签名。
- 土耳其、欧洲、美国、中东及其他：保持正式、非刻板印象和非绝对化建议。

每次只显示当前地区和输入相关的简短提示，并使用“通常建议”“可考虑”“仍应结合公司文化和熟悉程度”等措辞。

## AI 格式异常降级

1. 解析严格 JSON。
2. 移除 Markdown 代码块后解析。
3. 最多发起一次格式修复请求。
4. 第二次仍失败时，从原始响应中提取可识别的 Subject 和 Body。
5. 不向用户展示无效 JSON、代码块或分析原文。
6. 如果能识别邮件，则正常显示邮件，分析区显示“暂时无法完成完整分析，请人工检查邮件内容。”
7. 如果无法识别有效邮件，则使用现有安全中文错误，不显示原始响应。

## 案例交互

案例区使用折叠区域或独立页面控制密度。每个案例显示场景、输入、语气、地区和预期效果。“使用此案例”只更新对应模式的 session 字段，并切换到相关模式；不触发 API、风险确认或生成动作。

## 错误与状态

- 必填为空和长度超限仍在 API 前拦截。
- 高风险未确认时给出明确下一步。
- AI 错误继续使用安全中文提示。
- 解析降级、风险等级和本地化建议都有可读文字，不依赖颜色。
- 请求期间保留现有加载和重复提交保护。
- AI 服务状态继续显示配置、连接、耗时和可用 Token 用量。

## 测试策略

新增服务级单元测试和 Streamlit 页面测试，覆盖附件要求的 20 类场景：

- V1.0 与新产品名称
- 地区选项、未指定、其他地区
- 印度尼西亚与马来西亚规则
- 不推断 Mr./Ms.
- 凭证和长数字高风险、掩码及普通内容低风险
- 高风险确认前 API 调用为零
- 日志不含完整输入
- 沟通分析解析和非 JSON 降级
- 案例填充及零 API 调用
- 原有生成、优化、签名、错误和访问码测试继续通过
- 不持久化输入和结果
- Secrets 不暴露、不进入 Git

所有 AI 与网络调用使用 Mock，不产生真实费用。
