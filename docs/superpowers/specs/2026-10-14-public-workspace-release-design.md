## 5. 免登录费用保护与明确限制

原配额函数依赖已验证账号和活跃应用会话，不能用于匿名访问，也不能使用共享假账号或管理权限绕过。

本次采用不依赖新增服务的最小服务端保护：

1. 由进程内共享、加锁的计数器，在每次实际 DeepSeek 请求前原子检查并计数。
2. 每个服务端会话在 UTC 自然日最多 20 次实际 API 请求；整个应用进程当天最多 200 次。
3. 一个会话同时只允许一个在途 API 请求；异常也释放占用，过期占用最长 10 分钟。
4. 格式修复请求同样计次；保留最多一次格式修复和客户端 `max_retries=0`，不增加隐式收费重试。
5. 达到额度或已有请求时，先拒绝调用并显示中文提示，保留已输入与已生成内容。
6. 所有真实业务入口使用同一守卫；切页、刷新、复制、编辑和首页加载不会消耗模型额度。
7. 计数器仅保存随机会话标识、数量和时间，不记录 IP、账号、邮件或凭证。

**必须向用户披露的限制：**

- “20 次”是每会话限制，不是每人限制；新建会话可能获得新的会话额度，但仍受同一进程的总额限制。
- “200 次”是每进程、每 UTC 日限制，重启、重新部署或多实例会改变计数边界。
- 它是小规模免登录版的用量防护，不是跨重启、跨实例的硬预算，也不等于固定金额上限。
- 不通过未经授权的数据库变更、新服务或付费购买来掩盖这些限制。
- 若要求跨重启硬性日限额或严格按人配额，则需要持久化计量或身份方案，另行确认后才能扩大范围。

参考：[Streamlit 缓存概览](https://docs.streamlit.io/develop/concepts/architecture/caching)说明共享资源和线程安全要求；
[Reboot your app](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/reboot-your-app)说明重启可清除应用内存。
实施时同时核对已安装的 Streamlit 1.60.0 行为，不采用新版本才支持的接口。
