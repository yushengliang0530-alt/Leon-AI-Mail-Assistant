# v0.5 外部测试部署准备设计

## 目标

在不改变现有 DeepSeek 模型、API 地址、主要功能和中文主界面的前提下，使项目可以安全提交到 GitHub，并适合部署到 Streamlit Community Cloud。增加可选的小范围测试访问码，但不把它描述为正式身份认证。

## 访问保护

- 新建 `access_control.py`，集中处理访问码比较和门禁状态，便于未来替换成正式登录系统。
- `APP_ACCESS_CODE` 只从 Streamlit Secrets 读取，不写入代码、日志或页面状态信息。
- 未配置访问码时允许本地开发直接进入，并显示“测试访问保护尚未启用”。
- 配置访问码时，在主应用渲染前显示中文验证页。
- 使用恒定时间字符串比较，验证成功后仅在当前 Streamlit session 中保存布尔状态。
- 验证失败只显示中文提示，不调用 DeepSeek API，也不记录用户输入。

## 配置与运行环境

- `config.py` 扩展应用配置，继续保留现有 DeepSeek 模型和基础地址。
- 通过 Streamlit Community Cloud 提供的明确环境标志判断“本地开发”或“云端部署”，页面不显示路径、IP、环境变量或密钥信息。
- 增加 `runtime.txt`，指定 `python-3.12`；README 同时说明在 Community Cloud 高级设置中选择 Python 3.12。
- `requirements.txt` 只保留直接运行依赖并固定兼容版本范围。

## 隐私说明

在页面底部增加默认收起的“隐私与测试说明”：

- 用户输入会发送至 DeepSeek API。
- 不应输入密码、身份证号、银行卡、商业秘密或其他高度敏感信息。
- 测试阶段生成结果仅供参考，发送前应人工检查。

不对 DeepSeek 的数据保存或保留政策作未经证实的承诺。

## 安全与 Git

- 完善 `.gitignore`，覆盖 Secrets、虚拟环境、缓存、覆盖率和系统文件。
- 不读取或打印真实 `secrets.toml` 内容。
- 仅通过文件存在性、Git 索引和文件名扫描检查密钥安全。
- `.streamlit/secrets.toml.example` 只包含明确占位符。
- 初始化 `main` 分支，只暂存安全项目文件，不配置远程，不执行推送。

## 测试

- 单元测试访问码未配置、错误和正确三种情况。
- 验证门禁过程不会调用 DeepSeek。
- 保留生成、优化、缺少 API Key、输入保护、JSON 和签名测试。
- 使用模拟 DeepSeek 客户端，自动化测试不产生费用。
- 在临时目录创建 Python 3.12 优先的干净虚拟环境并安装 `requirements.txt`；若本机没有 Python 3.12，则使用可用解释器完成依赖安装，同时记录 Python 3.12 云端要求。
- 启动 Streamlit，检查应用能够加载。

## 成功标准

- 所有测试通过，应用可启动。
- 未配置访问码时不阻断本地开发；配置后门禁正确工作。
- Secrets 未被 Git 跟踪，仓库中没有疑似真实密钥或本地绝对路径。
- Git `main` 分支包含最终提交 `v0.5 Prepare external test deployment`，且没有远程上传。
